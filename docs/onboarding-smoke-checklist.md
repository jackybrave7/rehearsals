# Smoke-checklist: онбординг (перед merge / деплоем)

Ветка: `feature/onboarding-engagement`. После деплоя перезапустить API (drip-шаблоны v11).

## Демо ≤ 3 клика

1. Новый (или пустой) аккаунт режиссёра.
2. «Попробовать на примере» (приветствие или пустой экран).
3. Убедиться: открыта карточка репетиции с планом, показано превью / окно «Поделиться» (`?share=telegram`).

## Свой театр

1. Создать театр → участник → постановка (только название/автор) → 3 сцены → роль в составе → площадка.
2. «Новая репетиция» → «Создать и сформировать план» → план не пустой.
3. При коротком плане виден баннер «Не распределено …».

## Посещаемость

1. Будущая репетиция: фактическое присутствие не «Был(а)» по умолчанию.
2. RSVP подписано «Подтверждение участия».

## Экспорт

1. На карточке репетиции: «Поделиться планом», .ics, Google — с `aria-label`.
2. Скачанный .ics: `TZID`, `DTSTAMP` ≠ начало репетиции, в `DESCRIPTION` есть блоки плана.

## Чеклист и навигация

1. Полоса «Выполнено N из 9» на внутренних страницах.
2. «Пропустить, настрою позже» скрывает онбординг.
3. Пункт «Сейчас» в меню и на мобильном таббаре.

## Deep links (письма / URL)

| URL | Ожидание |
|-----|----------|
| `/app/overview?tryDemo=1` | Установка демо, переход к репетиции |
| `/app/rehearsals?planShare=1` | Ближайшая репетиция с планом + share |
| `/app/settings?tab=theater&focus=telegram` | Вкладка театра, фокус Telegram |

## Админка

1. Пользователи: последний вход, последняя активность, Telegram.
2. Карточка пользователя: блок «Сессия и онбординг», вехи после действий в приложении.
