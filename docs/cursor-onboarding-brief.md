# Задание для Cursor: доработка вовлечения новых пользователей в «Репетиции» (rehears.ru)

Репозиторий: jackybrave7/rehearsals (React + Express + SQLite).

## Контекст (данные админки на 10.11.2026)
- 22 внешних пользователя (без автора, его труппы и тестового аккаунта).
- 12 из 22 так и не создали театр.
- 6 создали театр и остановились (0 сцен / 0 репетиций).
- Только 3 внешних театра дошли до первой репетиции.
- Письма онбординг-цепочки почти не кликают: 3 клика за всё время, шаг «Telegram» — 0 открытий.
- Тестовый проход новичка до первого плана репетиции: 8 этапов, ~63 действия (48 кликов + 15 полей).

Цель: новый пользователь видит готовый план репетиции и сообщение для Telegram за 1–2 минуты, без Google Docs, без Telegram и без заполнения контактов.

## P1 — главное

### 1. Демо-постановка в один клик
- В приветственном окне, в пустом состоянии театра и на пустой странице постановок добавить кнопку «Попробовать на примере».
- Она создаёт отдельный демо-театр с постановкой, сценами, ролями, участниками (без контактов), площадкой и репетицией на ближайшую дату с уже сформированным планом. В коде уже есть сид «Каменное сердце» — использовать его.
- Демо-данные помечены как пример, их можно удалить одной кнопкой; демо не занимает лимит Free («один театр, одна активная постановка»).
- После создания сразу открывать план репетиции и показывать превью сообщения для Telegram.

### 2. Репетиция сразу с планом
- В форме новой репетиции кнопку «Создать и открыть план» заменить на «Создать и сформировать план»: черновик по выбранным сценам генерируется автоматически (хронологический режим по умолчанию).
- Убрать предупреждение «План по времени пуст — участникам нечего готовить» из формы создания (план там ещё нельзя собрать). Вместо него — нейтральная подсказка «Дальше соберём план по времени из выбранных сцен».
- Если план короче репетиции (пример: план 18:00–18:45 при репетиции 18:00–21:00), показывать «Не распределено 2 ч 15 мин» и предложить: растянуть сцены, добавить перерыв/разминку или сократить репетицию.

### 3. Посещаемость будущих репетиций
- Сейчас у будущей репетиции у всех участников по умолчанию стоит «Был(а)». Для будущих — «не отмечено»; «Был/не был» доступно только после начала репетиции.
- Разделить визуально: известные ограничения, подтверждение участия, фактическое присутствие.
- «все ожидаемые участники свободны» при отсутствии данных заменить на «Нет известных ограничений».
- «RSVP» в интерфейсе заменить на «Подтверждение участия».
- Проверить 404 на эндпоинте `/rsvp` для новой репетиции.

### 4. Укоротить первые формы
- Постановка: на первом шаге только «Название» и «Автор»; обложка, цвет, аватар, описание, Google Docs и загрузка пьесы — в свёрнутый блок «Дополнительно». Явно написать, что текст пьесы можно добавить позже.
- Участник: имя + «Добавить ещё»; телефон, email, Telegram, заметки и недоступность — в свёрнутый блок, с пометкой «необязательно».
- Сцена: название + минуты; прогноз хронометража (а.л., символы, множитель), формулы и заметки — под раскрытием.
- В приветствии не подавать импорт из Google Docs как обязательный второй шаг: «Добавить сцены вручную / Импортировать из Google Docs / Попробовать пример».

### 5. Явные ошибки
- В справке выводятся сырые шаблоны: «Добавьте {{Постановка}}», «Роли в {{Состав}}», «{{Площадка}}», «Первая {{Репетиция}}», «{{Театральный календарь}}» — исправить подстановку.
- Кнопки меню действий репетиции (Google Календарь, Файл .ics, Telegram, Удалить) не имеют доступных имён (aria-label пустой) — добавить.
- .ics: нет TZID/VTIMEZONE (время «плавающее»), DTSTAMP равен началу репетиции, в DESCRIPTION только ссылка. Добавить часовой пояс театра, DTSTAMP = время экспорта, текстовый план по блокам в описании.
- Опечатка «Бетта» в баннере и в названии демо-театра → «Бета».
- Склонения: «3 сцен», «1 сцен», «1 показов».

## P2 — навигация и модель данных

### 6. Чек-лист везде, а не только на главной
- Компактная полоса прогресса «Выполнено 3 из 9 · Дальше: Добавить сцены →» на всех страницах настройки, чтобы не возвращаться на главную после каждого шага (в тесте — 6 лишних возвратов).
- Счётчик «выполнено N из 9» вместо «шаг 2 из 9».
- Telegram отметить как необязательный; кнопка «Пропустить, настрою позже», после которой онбординг считается завершённым.
- Ссылка чек-листа «Telegram-бот: чат и участники» сейчас открывает вкладку настроек «Общие» — вести сразу на вкладку театра с Telegram.
- Блок «Требует внимания — Всё в порядке ✓» на пустом театре вводит в заблуждение: показывать незавершённую настройку.

### 7. Роли и состав
- Для новой постановки не показывать сразу «показы»: один состав по умолчанию; «Новый показ» — позже.
- Сетка распределения: строка «Роль — Актёр» с вводом роли и выбором/созданием участника прямо в строке, «Сохранить и добавить ещё». Сейчас 3 роли + 3 назначения = 13 кликов.
- Кнопки «Роль» переименовать в «Добавить роль»; «Добавить» у роли — «Назначить актёра».
- Предупреждение «нет email — личный кабинет не откроется» в пикере: смягчить до «Назначение работает; доступ в кабинет можно настроить позже».
- Отсутствие телефона/Telegram/ролей на карточках участников не показывать как ошибку.

### 8. Шапка и экспорт
- Шапка «Не выбран · Не выбрана · Не выбран» без подписей: скрывать пустой контекст или писать «Театр не создан».
- Тексты приветствия не должны ссылаться на «левое боковое меню» и «+ Новый», если в текущей теме меню справа.
- На странице плана — видимая кнопка «Поделиться планом» (Telegram / .ics / Google Календарь) вместо меню «⋮».
- Окно «Сообщение для Telegram»: сначала простое «Скопировать текст», техническое объяснение про ссылки — ниже; кнопка «Подключить чат театра» прямо в окне.
- Ссылка «Забыли пароль?» рядом с полем пароля на странице входа (справка на неё ссылается, а на странице её нет).

### 9. Сенсорный ввод
- «Состав при наведении» работает только при наведении мыши — нужен вариант для нажатия.
- Перетаскивание блоков плана: добавить кнопки «вверх/вниз» для телефона.
- Именованные кнопки редактирования вместо безымянных карандашей.

## P3 — справка и метрики
- Справка: «Восемь шагов» → девять; «Обзор» → «Сейчас»; «Премьера» → «Основной состав»; «Добавить» → «Пригласить». Генерировать подписи и число шагов из того же источника, что и интерфейс.
- Аналитика онбординга: события «создал театр / постановку / сцены / репетицию / сформировал план / экспорт / Telegram» с датой; в админке — последний вход и последняя активность каждого пользователя (сейчас их нет) и подключён ли Telegram.
- Онбординг-письма: в каждом письме одна кнопка, ведущая прямо на нужное действие (deep link), а первое письмо — ссылка на демо-постановку.

## Критерии готовности
- Новый аккаунт: от «Попробовать на примере» до открытого готового плана — не более 3 кликов.
- Свой театр с нуля до первого сформированного плана — не более ~25 действий (сейчас ~63).
- Нет сырых {{шаблонов}} в справке; у кнопок меню экспорта есть доступные имена; .ics содержит часовой пояс.
- Будущие репетиции не отмечают участников как присутствовавших.
